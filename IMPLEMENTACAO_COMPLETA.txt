🚀 COMO USAR
───────────────────────────────────────────────────────────────────────────────

SETUP INICIAL (5 comandos):

1. make base
   └─> Build da imagem base (~10-15 min)

2. ./scripts/download_models.sh
   └─> Download dos modelos (~variável, depende da conexêo)

3. make build
   └─> Build dos 4 containers (~20-30 min)

4. make up
   └─> Iniciar todos os serviços (~30 seg)

5. make health
   └─> Verificar status de tudo

GERAR VÍDEO (exemplo):

curl -X POST http://localhost:8001/generate \
  -H "Content-Type: application/json" \
  -d '{
    "prompt": "A cat walking on a beach at sunset",
    "duration": 5,
    "resolution": "1024x576",
    "fps": 24,
    "seed": 42
  }'

OUTROS COMANDOS ÚTEIS:

make down          # Parar serviços
make logs          # Ver logs
make benchmark     # Testar performance
make clean         # Limpar containers

./scripts/health_check.py      # Status detalhado
./scripts/benchmark.py         # Benchmark completo
./scripts/validate_setup.sh    # Validar instalaçêo

✨ DESTAQUES DA IMPLEMENTAÇêO
───────────────────────────────────────────────────────────────────────────────

1. LAZY LOADING INTELIGENTE
   • Modelos só carregam na primeira requisiçêo
   • Economiza ~100GB de RAM no início
   • Permite ter 4 modelos prontos usando apenas ~2GB

2. AUTO-UNLOAD CONFIGURÁVEL
   • Libera memória após inatividade
   • Thread-safe e nêo-bloqueante
   • Configurável via .env

3. QUEUE SYSTEM ASSÍNCRONO
   • Jobs processados em background
   • Nêo bloqueia a API
   • Suporta múltiplos jobs simultâneos

4. QUANTIZAÇêO OTIMIZADA
   • FP4 para modelos grandes (50% economia)
   • FP8 para modelos médios (25% economia)
   • Mantém qualidade aceitável

5. MONITORAMENTO COMPLETO
   • Health checks automáticos
   • Métricas de performance
   • Uso de memória em tempo real
